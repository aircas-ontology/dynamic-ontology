# 数据源构建对象接口说明

## 接口名称

- 数据源构建对象
- OpenAPI 控制器：`OntologyBuildFromDatasourceController`
- OpenAPI 操作：`OntologyBuildFromDatasourceController_buildObject`

## 文档状态

本文档已根据后端 OpenAPI 文档 `GET /ontology/v3/api-docs/ontology` 补全正式契约。

## 接口描述

在数据源构建对象向导中，用户完成数据库连接、数据表选择、字段选择和外键配置后，提交对象构建任务。服务端根据数据源、表、字段和关系配置创建本体对象及其属性、对象关系。

## 接口域

- `DOMAIN_CONFIG.ONTOLOGYMANAGE_URL`

## 接口 URI

- `/ontology/datasource/build_object`
- 操作标识：`OntologyBuildFromDatasourceController_buildObject`

## 请求方式

- `POST`

## 请求体

请求体使用 JSON，模型为 `OntologyBuildFromDatasourceParam`：

```json
{
  "spaceId": 1,
  "datasourceId": 1,
  "displayName": "舰船",
  "apiName": "ship",
  "categoryId": 1,
  "description": "我方舰船",
  "tables": [
    {
      "tableName": "ship",
      "master": true,
      "columns": [
        { "columnName": "id", "displayName": "舰船编号" },
        { "columnName": "name", "displayName": "舰名" }
      ]
    },
    {
      "tableName": "ship_weapon",
      "columns": [{ "columnName": "id" }, { "columnName": "ship_id" }, { "columnName": "weapon_name" }]
    }
  ],
  "foreignKeys": [
    {
      "childTable": "ship_weapon",
      "childColumn": "ship_id",
      "masterTable": "ship",
      "masterColumn": "id"
    }
  ]
}
```

### 页面数据到请求数据的映射

| 页面数据           | 当前实现位置     | 对接含义                                           |
| ------------------ | ---------------- | -------------------------------------------------- |
| `datasourceId`     | 数据源连接步骤   | 已保存或新建连接的数据源 ID；不重新提交密码        |
| `primaryTableId`   | 选表步骤         | 主表的页面 ID，当前等于表名                        |
| `selectedTableIds` | 选表步骤         | 选中的表 ID 列表，当前等于表名列表                 |
| `fieldIdsByTable`  | 字段步骤         | 每张表选中的字段 ID；字段 ID 当前由“表名-列名”组成 |
| `foreignKeys`      | 字段步骤         | 子表字段与主表字段的关联配置                       |
| `spaceId`          | 对象工作区上下文 | 当前空间 ID，提交时转换为整数                      |

### 请求字段

| 字段           | 类型                | 必填 | 说明                                     |
| -------------- | ------------------- | ---- | ---------------------------------------- |
| `spaceId`      | integer             | 是   | 本体空间 ID                              |
| `categoryId`   | integer             | 否   | 本体分类 ID，不传则不挂分类              |
| `displayName`  | string              | 是   | 对象展示名称                             |
| `apiName`      | string              | 是   | 对象 API 名称，同时作为主表物理表名      |
| `description`  | string              | 否   | 对象描述                                 |
| `datasourceId` | integer             | 是   | 数据源连接 ID                            |
| `tables`       | `SelectedTable[]`   | 是   | 至少一张表，其中恰好一张主表             |
| `foreignKeys`  | `ForeignKeyParam[]` | 否   | 子表到主表的外键列对，多表时每个子表一条 |

`SelectedTable` 包含 `tableName`、可选的 `master` 和至少一项 `columns`。`SelectedColumn` 包含必填的 `columnName` 及可选的 `displayName`。`ForeignKeyParam` 的 `masterTable`、`masterColumn`、`childTable`、`childColumn` 均必填。

## 响应

响应使用项目通用结构：

```json
{
  "code": 200,
  "message": "SUCCESS",
  "data": {
    "uniqueIdentifier": "ontology-object-identifier",
    "apiName": "ship",
    "displayName": "舰船",
    "propertyCount": 2,
    "entityTables": ["ship", "ship_weapon"],
    "mappingCount": 3,
    "message": "对象构建成功"
  }
}
```

`data` 类型为 `OntologyBuildFromDatasourceResultVO`，包含新建对象唯一标识、对象名称、属性数量、实体表名、列映射数量和提示消息。该接口为同步创建，不返回异步任务 ID。

## 状态码

以下为前端兼容处理建议，最终状态码和消息以后端文档为准：

- `200`：请求成功。
- `400`：请求参数、表字段或外键配置不合法。
- `401`：未登录或登录状态失效。
- `403`：无权在当前本体空间创建对象。
- `404`：数据源、数据表或空间不存在。
- `409`：对象或属性标识冲突。
- `422`：字段、主键或外键组合无法构建。
- `500`：服务端构建失败。

## 前置接口

最后接口对接前继续使用 [`1.datasourceConnectionApi.md`](../20261102/1.datasourceConnectionApi.md) 中的接口：

1. `POST /ontology/datasource/connection/test`：测试连接并取得可用数据源配置。
2. `GET /ontology/datasource/connection/table/list`：读取数据表摘要。
3. `GET /ontology/datasource/connection/table/columns`：读取字段、主键和外键候选。

最后接口只接收已确认的 `datasourceId` 和向导选择结果，不在构建请求中传递数据库密码。

## 前端对接方案

### 第一阶段：契约映射

已按正式契约新增 API 类型：

```ts
export interface BuildObjectFromDatasourceParams {
  spaceId: number;
  categoryId?: number;
  displayName: string;
  apiName: string;
  description?: string;
  datasourceId: number;
  tables: BuildObjectFromDatasourceSelectedTable[];
  foreignKeys?: BuildObjectFromDatasourceForeignKey[];
}

export interface BuildObjectFromDatasourceData {
  uniqueIdentifier: string;
  apiName: string;
  displayName: string;
  propertyCount: number;
  entityTables: string[];
  mappingCount: number;
  message?: string;
}
```

在 `src/types/index.ts` 统一导出，并在数据源 API 模块新增具名函数：

```ts
export function postBuildObjectFromDatasourceInterface(data: BuildObjectFromDatasourceParams): Promise<ApiResponse<BuildObjectFromDatasourceData>>;
```

请求函数通过 `request` 发起，使用 `DOMAIN_CONFIG.ONTOLOGYMANAGE_URL` 拼接正式 URI。

### 第二阶段：接入第四步提交

在 `DatasourceBuildDialog.vue` 的第四步提交逻辑中：

1. 先执行现有字段、主表和外键校验。
2. 将页面 ID 转换为后端需要的表名、列名和关系结构。
3. 设置提交状态，禁用“构建对象”按钮，防止重复请求。
4. 调用最后接口并检查 `response.code === 200`。
5. 成功时通知父页面关闭向导、刷新对象列表，并清理当前构建状态。
6. 失败时保留当前步骤、选择和错误信息，允许用户修改后重试。

### 第三阶段：同步或异步结果处理

- 若响应直接返回创建结果：成功后刷新对象列表，并定位到新建对象（如响应提供对象 ID）。
- 若响应返回任务 ID：增加构建任务状态轮询；轮询期间保留弹窗并展示进度，成功后再刷新列表。
- 页面卸载或弹窗关闭时取消未完成的请求或轮询，避免过期响应覆盖新状态。

### 错误与边界处理

- 数据源失效：提示重新测试连接，不重复提交密码。
- 表或字段在构建前被删除：展示服务端错误并允许返回选表步骤。
- 外键候选为启发式关系：仅提交用户明确确认后的关系。
- 对象标识冲突：保留配置，提示修改对象名称或标识。
- 重复点击：以提交状态锁定按钮，避免创建多个对象。
