# 接口名称

- 依据 actionApi 删除行为

## 编译位置

- apis：`src/apis/ontologyActionApi.ts`
- types：`src/types/apis/deleteOntologyActionType.ts`
- mocks：`src/mocks/deleteOntologyActionMock/deleteOntologyActionMock.ts`

## 接口来源

- Knife4j 文档：`http://172.16.18.58:37002/ontology/doc.html#/ontology/对象行为/OntologyActionController_delete/doc`
- 文档标题：`DELETE 依据actionApi删除行为`
- 文档定义的操作标识：`OntologyActionController_delete`

## 接口描述

- 根据行为 API 标识删除对象行为。
- `actionApi` 作为路径参数传递，服务端依据该标识定位并删除行为。

## 接口 domain

- `DOMAIN_CONFIG.ONTOLOGYMANAGE_URL`

## 接口 uri

- `/ontology/action/{actionApi}`

## 请求方式

- DELETE

## 请求参数

- `actionApi`：【string，必填，path】行为 API 标识。
- 请求不包含 JSON body、query 或 header 业务参数。

## 输入参数

- 传参方式：【必须】将 `actionApi` 放入 URL path。
- 示例：

```text
DELETE /ontology/action/satellite
```

调用前应校验 `actionApi` 去除首尾空白后不能为空，并对 URL path 参数进行正确编码。

## 输出参数

```JSON
{
  "code": 200,
  "message": "SUCCESS",
  "data": null
}
```

- `code`：【integer / int32】响应码
- `message`：【string】消息描述
- `data`：【unknown】业务响应数据；接口文档未进一步定义具体响应模型

## 响应状态码

- `200`：请求成功
- `400`：请求参数错误
- `401`：权限不足，请重新登录
- `500`：服务器内部错误

## message

- 成功时返回接口约定的成功消息，通常为 `SUCCESS`。
- 失败时返回具体错误信息。

## apis 示例

文件：`src/apis/ontologyActionApi.ts`

```ts
import type { ApiResponse, DeleteOntologyActionParams } from "@/types";
import { request } from "@/utils/request";

/**
 * 根据 actionApi 删除对象行为。
 *
 * 请求方式：DELETE `/ontology/action/{actionApi}`
 *
 * @param params 行为删除参数。
 * @param params.actionApi 行为 API 标识。
 * @returns 标准 API 响应，data 由服务端接口定义。
 */
export function deleteOntologyActionInterface(params: DeleteOntologyActionParams): Promise<ApiResponse<unknown>> {
  return request<unknown>({
    url: DOMAIN_CONFIG.ONTOLOGYMANAGE_URL + "/ontology/action/" + encodeURIComponent(params.actionApi),
    method: "delete",
  });
}
```

并在 `src/apis/index.ts` 中导出：

```ts
import { deleteOntologyActionInterface } from "./ontologyActionApi";

export { deleteOntologyActionInterface };
```
