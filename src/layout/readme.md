# Layout 目录规范

## 1. 目录职责与边界

`src/layout` 存放跨页面复用的应用骨架，例如顶栏、侧栏、工作区和路由内容出口。

- 【必须】布局只负责公共结构、区域编排和布局级交互。
- 【禁止】布局承载具体页面业务、领域数据加工或页面专属 API 调用。
- 【优先】通过路由出口和 Slots 承载页面内容。

## 2. 结构与命名

- 【必须】布局组件使用 PascalCase；单一默认布局可使用生态约定的 `index.vue`。
- 【必须】布局专属资源放入 `src/assets/layouts/<layoutName>`。
- 【优先】布局子区域达到独立职责时拆为同目录组件，避免空壳式拆分。

## 3. 类型、依赖与数据流

- 【必须】使用 Vue 3 Composition API 和 `<script setup lang="ts">`。
- 【必须】布局状态只描述导航展开、区域显隐等布局行为；跨页面业务状态交给 Store。
- 【禁止】直接依赖页面内部组件、页面私有类型或页面私有资源。
- 【优先】项目内部依赖使用 `@/`。

## 4. 布局与样式

- 【必须】常规布局优先使用 Grid 或 Flex，内容区域设置合理的 `min-width: 0`、`min-height: 0` 和 overflow。
- 【必须】使用 `--aircas-*` 主题变量并保持暗亮主题兼容。
- 【必须】以 `1920 × 1080` 为主要基准，同时验证更高桌面分辨率和窄容器。
- 【禁止】为视觉微调引入无业务语义的 DOM 层级。

## 5. 生命周期与异常

- 【必须】布局注册的全局监听器、Observer 和快捷键在卸载时移除。
- 【必须】布局级异步初始化提供 loading 和 error 反馈，不得阻断路由内容而无提示。
- 【优先】权限差异通过明确的路由或状态输入表达，不在模板中散布隐式判断。

## 6. 变更检查清单

1. 修改是否属于所有相关页面共享的结构。
2. 路由出口、尺寸收缩和滚动边界是否正确。
3. 是否误引入页面业务或页面私有依赖。
4. 暗亮主题、焦点和不同桌面尺寸是否验证。

## 7. 现状差异与后续整改

- 当前 `index.vue` 模板为空，但保留了多组未使用的布局样式，后续应在实际布局确定后同步模板与样式。
- 当前存在未使用的 Vue 导入，后续源码整理时应移除。
