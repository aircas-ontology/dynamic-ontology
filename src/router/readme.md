# Router 目录规范

## 1. 目录职责与边界

`src/router` 负责路由实例、路由模块装配、导航守卫和路由元信息，不承载页面业务。

- 【必须】`index.ts` 作为唯一装配入口，业务路由放入 `modules`。
- 【禁止】在路由配置或守卫中直接操作 DOM、实现页面数据请求流程或保存业务状态。

## 2. 结构与命名

```text
src/router/
├─ modules/
│  └─ <domain>Routes.ts
├─ index.ts
└─ readme.md
```

- 【必须】路由模块文件使用“小驼峰业务名 + `Routes.ts`”。
- 【必须】路由 `name` 使用唯一、稳定的 PascalCase 业务名称；path 使用小写 kebab-case。
- 【禁止】依赖数组顺序解决路由名称或路径冲突。

## 3. 类型、依赖与装配

- 【必须】路由记录使用 `RouteRecordRaw` 等 Vue Router 类型，类型导入使用 `import type`。
- 【必须】页面组件默认使用动态 import 懒加载；布局等首屏公共骨架可静态导入。
- 【必须】模块通过 `index.ts` 显式装配，禁止模块产生隐式注册副作用。
- 【优先】稳定的业务元信息建立类型声明，不在守卫中读取未经类型约束的字段。

## 4. 导航与守卫

- 【必须】认证、权限和重定向规则集中、可预测，并避免重定向循环。
- 【必须】守卫异常提供明确降级目标或错误处理，不静默放行失败状态。
- 【禁止】在守卫中发起无缓存、无取消或每次导航重复的重型请求。
- 【优先】业务跳转使用命名路由，路径只用于外部入口或明确的 URL 契约。

## 5. 生命周期与错误处理

- 【必须】动态注册的路由和守卫保存并调用对应移除函数。
- 【必须】懒加载失败、无权限和未知路径具有明确处理策略。
- 【优先】导航日志不得包含令牌、凭据或敏感查询参数。

## 6. 变更检查清单

1. 路由是否归入正确模块，name 和 path 是否唯一。
2. 页面是否懒加载，模块是否由入口显式装配。
3. 守卫是否无循环、无重复重型请求且错误可见。
4. 页面跳转目标与路由 name 是否一致。
5. 关键登录、鉴权、无权限和 404 流程是否验证。

## 7. 现状差异与后续整改

- `ontologyRoutes.ts` 当前为空且装配被注释，后续应根据实际页面路由补齐或移除占位模块。
- 登录页跳转使用 `OntologyDomain`，当前路由表未定义该名称，后续应统一。
- 全局守卫存在未使用参数和占位实现，后续应在真实规则确定后精简。
