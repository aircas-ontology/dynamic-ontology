# Utils 目录规范

## 1. 目录职责与边界

`src/utils` 存放无页面状态、可复用的工具函数，以及边界清晰的基础设施适配器。

- 【优先】工具保持纯函数：相同输入得到相同输出，不修改传入对象。
- 【禁止】维护页面或业务共享状态；此类状态属于 Store 或领域服务。
- 【禁止】普通工具直接操作 DOM、路由或组件实例。

## 2. 文件与符号命名

- 【必须】普通 TypeScript 文件使用 camelCase，名称准确表达能力或适配边界。
- 【必须】函数和变量使用 camelCase，导出常量使用有单位或语义的明确名称。
- 【优先】使用具名导出；只有模块确有单一主导对象时才使用默认导出。
- 【禁止】使用 `common.ts`、`helper.ts`、`utils.ts` 等宽泛文件名。

## 3. 类型与依赖

- 【必须】参数和返回值保持类型安全，公共业务类型从 `@/types` 导入，纯类型使用 `import type`。
- 【必须】外部数据在工具边界按 `unknown` 接收并通过类型守卫或明确校验收窄。
- 【优先】项目内部模块使用 `@/`，避免跨目录深层相对路径。
- 【禁止】为省略错误处理使用 `any` 或无依据的类型断言。

## 4. 副作用与错误处理

- 【必须】HTTP、Storage、地图初始化等副作用工具在名称、参数和文档中明确其边界。
- 【必须】错误包含可定位上下文，并由调用方决定业务提示；禁止静默吞掉异常。
- 【必须】输入值、浏览器能力或运行时配置无效时快速失败或返回可区分的类型结果。
- 【禁止】日志输出令牌、密码、完整请求体或其他敏感信息。

## 5. 实例与生命周期

- 【必须】Cesium、Mars3D、ECharts、Three.js 等实例只初始化一次并具有明确所有者。
- 【必须】实例、监听器、定时器、动画帧、Observer 和附加 DOM 资源提供完整清理函数。
- 【禁止】模块被 import 时自动创建并启动长期运行的实例。
- 【禁止】将第三方复杂实例交给 Vue `reactive()` 深度代理。

## 6. 变更检查清单

1. 能力是否无业务状态且适合跨模块复用。
2. 文件名、具名导出、输入和返回类型是否明确。
3. 外部输入、异常和敏感日志是否正确处理。
4. 副作用是否可测试、可取消、可释放。
5. 是否包含正常、边界、错误和重复调用测试。
