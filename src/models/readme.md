# Models 目录规范

## 1. 目录职责与边界

`src/models` 存放具有明确业务概念、行为和状态约束的领域模型或 Class。

- 【必须】模型封装领域规则，不负责页面渲染、DOM、路由或 HTTP 请求。
- 【禁止】把无状态通用函数、接口 DTO 或 Vue 响应式状态放入本目录。
- 【优先】只有同时具有状态与行为的概念才使用 Class；简单数据结构放入 `src/types`。

## 2. 文件与符号命名

- 【必须】以 Class 为主要导出的文件和类使用 PascalCase，文件名与类名一致。
- 【必须】方法、属性和普通辅助函数使用 camelCase，常量使用表达业务含义的 camelCase。
- 【禁止】使用无业务含义的 `Manager`、`Helper`、`Data` 等宽泛命名。

## 3. 类型、依赖与状态

- 【必须】构造参数、公共属性、方法参数和返回值具有明确类型。
- 【必须】模型使用的公共业务类型从 `@/types` 导入，纯类型使用 `import type`。
- 【必须】校验外部输入和关键不变量，非法状态应尽早失败并给出明确错误。
- 【优先】字段保持私有或只读，通过方法返回新数据，限制外部直接修改内部状态。
- 【禁止】模型依赖 Vue 组件实例、Pinia Store 或浏览器 DOM。

## 4. 行为与错误处理

- 【必须】方法只处理该模型职责内的领域行为，失败语义通过类型、明确异常或可空结果表达。
- 【禁止】静默吞掉第三方计算库异常或返回无法区分原因的占位值。
- 【优先】时间、随机数和外部算法适配器可注入，以保证测试确定性。

## 5. 生命周期与资源

- 【必须】持有定时器、动画帧、监听器或订阅的模型提供 `pause`、`stop` 或 `dispose` 等明确清理能力。
- 【必须】清理操作可重复调用且不会残留回调。
- 【禁止】仅因模块被导入就启动长期后台任务。

## 6. 变更检查清单

1. 代码是否确属有状态、有行为的领域模型。
2. 输入、不变量、可空结果和失败语义是否明确。
3. 内部状态是否受到封装，调用方是否难以制造非法状态。
4. 时间、第三方算法和后台资源是否可测试、可释放。
5. 是否具有模型级单元测试和边界用例。

## 7. 现状差异与后续整改

- `SatelliteClass` 暴露较多可变字段且构造输入缺少明确校验，后续应收紧状态边界。
- `TimeEngine` 可暂停动画帧，但缺少统一销毁并清空订阅的接口，后续应补充完整生命周期。
